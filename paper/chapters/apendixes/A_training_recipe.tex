\section{Training recipe}
\label{app:training}

We train on ImageNet-1k~\citep{deng2009imagenet} at $224{\times}224$.
\Cref{tab:app-training} lists the full hyper-parameter table, next to the official
ConvNeXt-T recipe~\citep{liu2022convnext}.
The four models we train from scratch share the same augmentation, regularisation and
optimiser; they differ in peak learning rate, warmup length, minimum learning rate,
stochastic depth and parallelism, as marked in the table.
The official ConvNeXt-T uses batch size $4096$ and base learning rate $4{\times}10^{-3}$.
Linear scaling to our batch of $1024$ gives $1{\times}10^{-3}$, which is the peak we use
for the weight-tied and all-stages runs.
The untied ConvNeXt-T and its drop-path-free sibling use half of that,
$5{\times}10^{-4}$, with the official $20$-epoch warmup.
The untied runs use one process with \texttt{DataParallel} over a batch of $1024$; the
tied and all-stages runs use four distributed processes with $256$ images each.
Mixup and CutMix are drawn per process batch, so the mixing statistics are not
identical between the two set-ups.
No run fixes a random seed, so the accuracy gaps of \cref{sec:weight_tied} come from
single runs under recipes that are close but not matched.

Weight decay is applied only to convolution and linear weights (tensors of rank
$\ge 2$).
LayerNorm gain and bias, convolution/linear bias and LayerScale $\gamma$ are decay-free,
following the ConvNeXt / DeiT convention.
Convolution and linear weights are initialised with truncated normal $\mathcal{N}(0,0.02^2)$;
LayerScale uses $\gamma{=}10^{-6}$.
There is no layer-wise learning-rate decay, no gradient clipping, no mixed precision and
no exponential moving average of the weights.
The learning-rate schedule is a linear warmup (starting at $10^{-6}$) followed by cosine
decay to the listed minimum, advanced once per optimiser step.

Mixup and CutMix are applied to every training batch (switch probability $0.5$), and the
loss is soft-target cross-entropy on the mixed labels.
Per-image augmentation is the timm ConvNeXt stack: random resized crop, horizontal flip,
RandAugment \texttt{rand-m9-mstd0.5}, color jitter $0.4$ and random erasing
(probability $0.25$, pixel mode).
Validation uses the standard centre crop.
Stochastic depth, when enabled, is ramped linearly from $0$ to the listed peak across the
$18$ residual blocks.
In the weight-tied model it is applied per application of the shared block: the $k$-th
application in stage~3 uses the rate of the $k$-th untied stage-3 block,
$\mathrm{linspace}(0,0.1,18)[6{+}k]$, i.e.\ $0.035$ to $0.082$, so both models drop the
same expected fraction of stage-3 updates.

\paragraph{Stage-4 and head finetune after refinement.}
The decoder-adaptation result of \cref{sec:indefinite_looping} starts from the final
weight-tied checkpoint, freezes stem, stages~1--2 and the shared block, refines stage~3
to $128$ applications ($\Delta t{=}9/128$) and trains only stage~4, the global pool and
the classification head; we checked that every frozen tensor is bit-identical to the
starting checkpoint.
It runs $50$ epochs with no warmup and a cosine schedule from $10^{-6}$ to $10^{-8}$,
with the optimiser, weight decay, batch size and augmentation of
\cref{tab:app-training}.
Top-1 goes from $80.14\%$ to $80.33\%$ at the last epoch ($80.34\%$ at the best,
epoch $28$).
The script of that run is no longer in the repository, so we cannot check whether the
frozen stages ran with stochastic depth active.

That check matters: our later finetuning script left the frozen stages in training
mode, so stochastic depth kept dropping stage-3 updates during finetuning while
evaluation used the full stage.
We discard the runs made with it.
The corrected protocol (\texttt{scripts/finetune\_s4\_head\_protocol.py}) keeps every
frozen module in evaluation mode, asserts that no stochastic-depth layer outside stage~4
is active, uses a constant learning rate $5{\times}10^{-6}$ for $10$ epochs with seed
$0$ and evaluates the unmodified decoder before training as epoch $0$.
